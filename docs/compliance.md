## Оставшиеся эксплуатационные ограничения

- Внешние Vercel и R2 не подключены и не проверены с реальными credentials. Для браузерной загрузки нужно разрешить origin сайта в CORS bucket и указать корректный публичный HTTPS S3 endpoint.
- В API пока нет ограничения частоты регистрации/входа и квот на объём загрузок по аккаунту. Подписанный URL ограничен ключом объекта и 15 минутами, но фактический размер отклоняется после передачи; production deployment должен добавить storage quotas/лимиты и мониторинг расходов.
- Bearer token хранится в `localStorage`; это удобно для демо, но при появлении XSS даст доступ к активной сессии. В интерфейсе пользовательский текст экранируется; для production стоит перейти на `HttpOnly`, `Secure`, `SameSite` cookie и добавить CSRF-защиту.
- TLS, host allowlist, CSP, rate limiting и backup policy должны быть настроены на платформе/перед production-публикацией; они не подтверждены этим локальным репозиторием.
- На Vercel переменная `VIDEO_WORKER_ENABLED=false` оставляет исходный файл без FFmpeg нормализации и генерации миниатюры. Полный worker-сценарий доступен через Docker Compose.
- Варианты HLS/DASH не создаются. Видео хранится и выдаётся как исходный файл либо MP4 после локальной обработки.
- Схема таблиц сейчас создаётся через SQLAlchemy `create_all`; миграции для обновления долгоживущей базы ещё не добавлены.
- Проверка `docker compose config` и реальный cold deploy не выполнены: Docker отсутствует в среде. Полный набор автотестов локально проходит.
